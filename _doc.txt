TaskForge Collaborative Project Management Platform: Mid-Term Project Examination – Building the TaskForge Collaborative Project Management Platform Backend
Web Technology and Internet · AUCA · Functional requirements · Individual work · 100 marks + 10 bonus
1. Context
TaskForge helps a software team plan and follow the work of its projects. A project owns tasks that are carried out by a team member who sits at one workstation and has several skills; a task moves from OPEN to IN_PROGRESS and ends DONE or DROPPED. When a task is done, the team member records the work logs showing the hours spent.
In class and in the two quizzes you built the Kigali Clinic API (Patient, Doctor, Office, Specialization, Appointment, Prescription). In this examination you build the same kind of backend for your own project, TaskForge Collaborative Project Management Platform, with Spring Boot, Spring Data JPA and PostgreSQL. The six entities of TaskForge Collaborative Project Management Platform play the same roles as the clinic entities: Project (the project the work is done for), TeamMember (who handles it), Skill (a classification a team member can hold several of), Workstation (where a team member is assigned), Task (the dated transaction with a status) and WorkLog (a record written only after the task is DONE).

10. Hints
•  JPQL uses entity and field names, never table or column names: FROM Task e WHERE e.dueDate ...
•  Single-valued relations are navigated with a dot, no JOIN needed: e.teamMember.workstation.name or d.task.project.projectCode. Collections need a JOIN: JOIN p.skills c.
•  Enum values: pass them as a parameter, or write the fully qualified name of TaskStatus.DROPPED in the query.
•  UPDATE and DELETE queries need @Modifying on the repository method and @Transactional on the service method. They return int.
•  A many-to-many link is stored by the owning side, the entity with @JoinTable (TeamMember). Change its list and save it: teamMember.getSkills().add(x); teamMemberRepository.save(teamMember);
•  Workstations without a team member, with a subquery: SELECT l FROM Workstation l WHERE NOT EXISTS (SELECT p FROM TeamMember p WHERE p.workstation = l)
•  Dates: LocalDate.now(), date.isBefore(LocalDate.now()). Enums are compared with ==, e.g. status == TaskStatus.DONE.
•  Derived keywords needed: IgnoreCase, OrderBy...Asc, Between, Not, existsBy, StatusNot, countBy. The property name must match the Java field exactly.
•  The work log JSON will show its task, project and team member. If you add a List<WorkLog> to Task anyway, mark it @JsonIgnore to avoid an endless JSON loop.
•  Keep spring.jpa.show-sql=true. When a query returns nothing, read the generated SQL in the console.
